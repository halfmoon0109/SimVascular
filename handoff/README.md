# 에이전트 소통 문서 (handoff/)

Claude Code와 Codex가 같은 브랜치에서 번갈아 작업하며 주고받는 피드백을
**날짜별 파일 하나**에 시간순으로 적는다. 사람(사용자)이 같이 읽고 끼어들 수 있다.

## 파일
- `handoff/YYYY-MM-DD.md` — 그 날의 대화. 작업 시작 시 **가장 최근 파일**부터 읽는다.
- 날짜가 바뀌면 새 파일을 만들고, 이전 파일의 `## 열린 항목`에서 아직 열린 것을 새 파일로 옮긴다.

## 파일 구조
```
# YYYY-MM-DD — 브랜치명

## 열린 항목
- [ ] (번호) 한 줄 요약 — 담당: Claude|Codex|사용자 (제기: 항목 링크)
- [x] 닫힌 것은 체크하고 닫은 항목 번호를 적는다

## 기록
### HH:MM [Claude] 제목            ← 작성자 태그: [Claude] [Codex] [사용자]
- 한 일: …
- 커밋: `해시` 요약 (여러 개면 줄 나눔)
- 검증: 무엇을 어디까지 확인했는지 (Mac에서는 정적 검증만이라고 명시)
- 요청 → Codex: … (상대에게 원하는 것; 없으면 생략)
- 질문 → 사용자: … (판단이 필요한 것; 없으면 생략)

### HH:MM [Codex] 제목
- 답변 → #항목번호: …          ← 앞 항목에 대한 답은 번호로 가리킨다
- 발견: [P1|P2|P3] 파일:줄 — 무엇이 왜 문제인지, 재현/계산 근거
- 제안: …
```

## 규칙
- **항목 번호**는 파일 안에서 유일하게 `#1, #2, …`로 매기고, 답변·닫기는 번호로 가리킨다.
- 발견에는 **근거**(파일:줄, 재현 입력, 계산값)를 붙인다. "~할 수 있다"만으로는 열지 않는다.
- 상대 의견에 동의하지 않으면 **왜**를 쓰고 사용자 판단으로 넘긴다(`질문 → 사용자`).
- 코드 수정은 커밋 규칙(`[작업자] 타입: 요약`)대로 하고 여기엔 해시만 적는다. 코드 설명을 여기 길게 옮기지 않는다.
- 빌드/실행 결과(Windows·Docker)는 사용자가 붙여 넣거나 `logs/`에 커밋하고, 여기엔 **판독**만 적는다.
- 이 폴더의 파일은 코드 커밋과 분리해 `[작업자] docs: handoff YYYY-MM-DD` 로 커밋한다.
